WHY I'M BUILDING IT

I have always loved games that simulate a whole world, like Europa Universalis and Victoria.

Bread and Steel is my attempt at the game of my dreams: a painted realm where every town, market and wagon belongs to one living economy.

For years that stayed a daydream. A simulation this deep usually takes a studio: years of engineering and a team of artists.

AI lowers that barrier, in time and in artistic skill, though not in judgment. So I decided to build it, and brought the habits I rely on at work: contracts, tests, measurements and blind reviews.

THE WORLD

A painted world, generated from a seed.

3200 × 2750 cells, 160 provinces, 681 locations. Every image here is a 1920 × 1080 capture of the running game. No editor views, no paint-overs.

THE SIMULATION

A working economy under the paint.

Markets.
160 provinces each run a market with its own stock and prices for 40 goods, from food to enchanted reagents.
Convoys.
Wagons carry goods between markets along the roads. Whoever builds a Carters level owns the convoy it adds: the crown, a province or an Order.
Money.
Coin enters when people consume and leaves through upkeep, so every coin has a source and a sink.
Orders.
Four Orders (Arcane, Artisans, Martial, Faith) hold the realm's trades and its people. They grow on their own, petition, and strike.
Deterministic.
One tick is one day. State is integers only. The same seed gives the same world and the same economy, byte for byte.

In development. The economy runs and is tested; the player's full loop and balancing are still being built.

HOW IT'S BUILT

I direct. Agents implement. Gates decide what lands.

Every change goes through the same loop. I own intent and taste. A main Claude Code session turns that into a bounded contract and hands it to a specialist agent. Nothing lands until the gates pass. High-risk code faces an adversarial critic, and visual work a blind reviewer.

  1. 01

    Intent.

    I set what the game is and how it looks. The main session owns architecture and turns that into contracts: goal, constraints, invariants, proof of done.

  2. 02

    Specialists.

    dev writes C#. blender-modeler bakes Blender and Meshy models into deterministic C#. asset-gen draws 2-D art. Two read-only designers return options with formulas.

  3. 03

    Review.

    On high-risk changes, code-critic tries to break the code without seeing the implementer's reasoning, and qa re-measures the claim it rests on.

  4. 04

    Gates.

    Build, tests, determinism hashes against goldens, a frozen frame's SHA-256 and a performance run, all again before every push.

  5. 05

    Blind review.

    Screenshots go to a separate model as A and B, with no history, so it can't tell which is newer.

  6. 06

    The call.

    Review is advisory. Taste, tradeoffs and anything a player sees stay with me.

DISCIPLINE

Same seed, same world.

The rule everything rests on: world generation and the whole simulation live in a 53,000-line C# library with zero engine references. Godot only draws it, so every test and every determinism hash runs headless.

  • 620tests in the Release suite, run before every push
  • 32engine hashes, including a 360-day economy run, checked against recorded goldens
  • SHA-256of a frozen frame must match byte for byte
  • 7.5 msmean frame time at 1920 × 1080 with 5 M triangles on screen (RTX 5070 Ti, vsync off), re-measured on every per-frame change

EVIDENCE

I measure the setup, not just the output.

Instructions and critics are code too, so they get tests.

Do the instructions change what agents do?

I replay real tasks from this repository's history through claude plugin eval: no instructions versus the current CLAUDE.md and agent files, three runs each, graded by a separate model.

On these five replayed tasks, the instructions decide who does the work: routing goes from about 0.1 to 1.0. On the three code tasks the results are within noise (3/3 and 3/3 twice, 0/3 against 1/3), so they don't measurably change the code itself. A research-built rewrite did worse on one task (3/3 to 1/3) and was not adopted.

Does an AI critic see what I see?

25 past A/B decisions I made on screenshots, replayed to a critic that never sees my verdict.

On these 25 decisions, agreement is about two in three. That is useful for catching regressions and nowhere near taste, so critic feedback stays advisory.
